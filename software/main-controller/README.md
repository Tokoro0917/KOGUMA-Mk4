# main-controller

KOGUMA MK4 メイン基板(STM32H562RGV6。2026-11-26 に STM32H725RGV6 から替えた)のファームウェアです。**ToraNeko.Mk3 のファームウェア(`Tokoro0917/toraneko.mk3` の `software/main-controller/`)と同じ作り**にします(2026-11-23 決定)。ToraNeko の `App/` のコードを元にし、MK4 で違う所を直します。

- [../../docs/software.md](../../docs/software.md): ソフトの設計(ToraNeko との違い、時刻の作り方、制御、保存、ログ、テスト、作る順)
- [CUBEMX_SETUP.md](CUBEMX_SETUP.md): CubeMX(`.ioc`)の設定値(ステップ0)
- [MODES.md](MODES.md): 機体の操作、LED・ブザーの表し方、モードの割り当て
- ピン: [../../docs/pinmap.md](../../docs/pinmap.md)
- RAM・キャッシュ・DMA の決まり: [../../docs/firmware_memory.md](../../docs/firmware_memory.md)
- 無線(BLE)とブートローダ: [../../docs/ble.md](../../docs/ble.md)。ブートローダは [../bootloader/](../bootloader/README.md)、HY0020 は [../ble/](../ble/README.md)、無線で書き込む道具は [tools/fw.py](tools/fw.py)
- ビューア(ログを見る・コマンドを送る・書き込む。Chrome・Edge で開く): [../viewer/](../viewer/README.md)
- コマンドで動かす道具: [tools/mouse.py](tools/mouse.py)(状態・コマンド・走らせてログを取る・書き込み・ログのまとめ。Claude が作者の PC の上で動かせるように作った)。試すときは、にせの機体 [tools/fake_mouse.py](tools/fake_mouse.py) を相手にする
- コードの書き方: リポジトリの一番上の [CLAUDE.md](../../CLAUDE.md)(ToraNeko と同じ)

## モード一覧(今のファームウェアで選べるもの)

`KOGUMA-Mk4/App/sys/mode.c` に入っているモードと No.(2026-11-28)。**ToraNeko.Mk3 のモード一覧と同じ並び**で、寸法・速さをクラシック(16 × 16、180mm)に直し、MK4 で足したもの(太字)を入れた。
**モードを足したり変えたりしたら、同じコミットでこの表と [MODES.md](MODES.md) も直す。** **どれもまだ実機で走らせていない**(値は計算・仮の値。実機で合わせる)。
表にない番号は、スイッチを押しても決定しない(No.0 も同じ)。始め方は ToraNeko と同じ(スイッチで決定 → 前センサに手をかざして離す、またはスイッチを 1 秒以上押し続けて離すと 1 秒後に始まる)。
**PC・BLE の `run <モード> <No.>` でも同じモードを選べる**(手をかざして離すと始まる。`docs/ble.md` の 4.2)。

## 決定事項

| 項目 | 決定 | 理由・補足 |
|---|---|---|
| 作り | ToraNeko.Mk3 と同じ(フォルダ・層・名前・書き方・操作・テスト・ステップ) | 2026-11-23 ユーザーの決定 |
| 開発環境 | `Core/` は CubeMX と同じ形で **Claude が手で書いた**(2026-11-28、ユーザーの決定)+ CMake + VS Code | CubeMX を使える環境がなかったため。あとで CubeMX で `.ioc` を作って生成し直しても、`USER CODE` 欄と `App/` は残る(`CUBEMX_SETUP.md` の 0 章) |
| ビルド | `KOGUMA-Mk4/` で `cmake --preset Debug && cmake --build --preset Debug` | 成果物は `build/Debug/KOGUMA-Mk4.elf`・`.hex`・`.bin`。2026-11-28 で Flash 173KB(Release 123KB)/ 448KB |
| プログラムの番地 | **0x08010000 から**(先頭の 64KB はブートローダ) | 最初にブートローダ(`software/bootloader/`)を STLINK で書いておく。そのあとは STLINK でも無線・有線の `fw.py` でも書ける |
| 書き込み・デバッグ | STLINK-V3MODS(J7) | IWDG(約 50ms)はデバッガで止めているあいだは止まる |
| 電源 | **LDO**、VOS0 | H562 の VFQFPN68 は LDO だけ |
| クロック | HSE 10MHz → 240MHz | 上限は 250MHz。TIM1 の 80kHz・20kHz が割り切れる |
| 時刻の元 | TIM1(モーターの PWM 80kHz、センターアラインド) | 20kHz で ADC1・ADC2 の injected を起動 → **ADC2 の割り込みが 20kHz の処理**(電流の制御・壁センサの順番)→ 5 回に 1 回 TIM6 の割り込みで **4kHz の処理**(エンコーダ・IMU・速度・角度の制御) |
| DMA | **使わない**(2026-11-28) | ADC は injected、SPI は 4kHz の処理で直接、UART は割り込み(`CUBEMX_SETUP.md` の 0 章) |
| UART | USART1(PB6・PB7)、115200bps、送る・受ける | 有線(TP1)と BLE を同じ 1 本で。XON・XOFF を見る |
| 迷路 | **クラシック 16 × 16、1 区画 180mm** | ToraNeko(ハーフ 32 × 32、90mm)から直した |
| 機体の値 | タイヤ 24mm の機体(t24) | `config/robot_params.h` |

## 実装の進め方

各ステップで「ToraNeko の該当するコードを読む → MK4 で変える点を決める → 作る → 実機・PC で確かめる」。中身は [../../docs/software.md](../../docs/software.md) の13章。
**2026-11-28: 0〜13 のコードを一通り書いた**(ユーザー: 全部を順に)。PC のテスト(`test/` の `make`、11 本)とビルド(警告 0)まで。**実機は全部これから**なので、下の「確かめること」を順に試す。

| # | 内容 | 状態 | 実機で確かめること |
|---|---|---|---|
| 0 | `Core/`(240MHz、LDO・VOS0) | 書いた | 書き込めて動く(ブートローダ → 0x08010000)。だめなら TP4 で復旧 |
| 1 | LED・ブザーとシリアル | 書いた | 起動の表示(`KOGUMA-Mk4 boot`)、ロード中、音 |
| 2 | TIM1 と 20kHz・4kHz の処理 | 書いた | 処理の時間と間隔(`scheduler_take_stats`) |
| 3 | エンコーダ(MT6835) | 書いた | 手で回した向き(`ENCODER_*_SIGN`)、CRC のエラー 0、校正(モード6 No.5) |
| 4 | IMU(LSM6DSR) | 書いた(ToraNeko のまま、6660 回) | 回したときの符号、静止のノイズ |
| 5 | モーターの PWM と電流の読み取り | 書いた | 回る向き(`MOTOR_*_SIGN`)、0A の値、電流の向き |
| 5a | 電流の制御とモーターの同定 | 書いた(モード4 No.14・15) | ステップの応答で `CURRENT_KP`・`KI`、R・Ke |
| 6 | 壁センサ | 書いた | 値の大きさ(`log sensor`)、表(`wall_dist.c`)・しきい値を決め直す |
| 7 | 速度・角度の制御 | 書いた(電流の目標を出す形) | 直進・その場旋回をログで。`config/ctrl_gains.h` を合わせる |
| 8 | 迷路探索と最短経路 | 書いた(16 × 16 に直した) | PC のテストは通る |
| 9 | 探索走行、モード、ログ、フェイルセーフ、保存 | 書いた | 16 × 16 で通す。電源を切っても迷路が残る |
| 10 | コマンドと値の保存 | 書いた(`set` で変えられるのは 4 つ) | `set` → `save` → 入れ直しても残る |
| 11 | BLE | `@link` を見て状態の LED 0 に出す。走り終わりに自動で送る | 無線で同じことができる |
| 12 | ターンの自動調整 | `run turn_test <No.>` で走り、ログが戻る。ターンの値はまだ `set` で変えられない | |
| 13 | ブートローダと無線の書き込み | 走るプログラムの側(0x08010000、`fw begin` で印を書いてリセット、起動の `#STATUS`)も書いた | `fw.py`・ビューアで書ける |

まだないもの: 探索の判断のログ(`explore`)、ログの Flash への保存、ターンの値を `set` で変える、電池の電流の見張り(7.5A)、モーターの温度の見張り(I²t)、回生の制限、IMU の加速度を速さの推定に使う(今はログだけ)。
