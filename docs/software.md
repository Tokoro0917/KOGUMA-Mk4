# KOGUMA MK4 ソフトの設計

2026-11-23 作成。回路は `hardware/kicad/KOGUMA-Mk4/`、ピンは `docs/pinmap.md`、制御の考え方は `docs/control.md`、無線とブートローダは `docs/ble.md`、RAM・キャッシュ・DMA の決まりは `docs/firmware_memory.md`。この文書は、それらをソフトの作りとしてまとめたもの。

## 0. 方針

- **MK3(`KOGUMA.MkIIl`、STM32F446)の資産を活かす**。迷路・最短経路・速度計画・壁の距離変換・柱の端・ログの形・ビューア・PC のテストは、ハードに依らないのでそのまま持ってくる。ハードに触る所と制御は作り直す
- **MK3 の反省(`KOGUMA.MkIIl/docs/next_robot.md`)を最初から作りに入れる**: 電流・左右の車輪の速度・電池をいつもログに残す、モーターの定数を実測で決める、ADC を読む時刻をタイマーで決める、会場ごとの値を Flash に保存する、RAM を気にしない
- **速さが要る処理だけを割り込みに置き、ほかはメインのループ**。割り込みは「周期が決まっていて短いもの」だけ
- **周期を定数で書かない**。MK3 の `INTERRUPTTIME`(1ms)のような決め打ちをやめ、各処理の周期を変数(`dt`)で渡す。周期を変えても式を直さなくてよい
- **1つずつ確かめながら進める**(13章)。一度に全部入れない

## 1. 全体の形

```
                 ┌──────────── メインのループ(優先度なし)───────────────┐
                 │ モード選び・走る手順(探索・最短・テスト)・迷路の計算      │
                 │ コマンド(UART/BLE)・Flash への保存・ログの送信            │
                 └────────────┬───────────────────────────────────┘
                              │ 目標(軌道)・状態の読み書き(共有の構造体)
 ┌─────────────────────────────┴──────────────────────────────────┐
 │ 1kHz   軌道の生成 → 位置・向き → 速度・角速度 → 電流の目標、壁制御、     │
 │        フェイルセーフ、ログ                                         │
 ├────────────────────────────────────────────────────────────────┤
 │ 10kHz  エンコーダ(SPI2 + DMA)→ 速度の推定(エンコーダ + 加速度)       │
 │ 6.66kHz IMU(INT1 → SPI3 + DMA)                                    │
 ├────────────────────────────────────────────────────────────────┤
 │ 20kHz  モーターの電流(ADC2)→ 電流の制御 → duty、電流の守り、         │
 │        壁センサの点灯と読み取り(ADC1)の順番                          │
 └────────────────────────────────────────────────────────────────┘
      TIM1(モーターの PWM)がすべての時刻の元。ADC は TIM1 で起動する
```

## 3. MCU の設定

| 項目 | 設定 | 理由 |
|---|---|---|
| 電源 | **Direct SMPS**(CubeMX の初期値の LDO にしない) | VFQFPN68 は SMPS だけ。LDO のまま書くと応答しなくなる(復旧は TP4、`docs/firmware_memory.md`) |
| クロック | HSE 10MHz(Y1)→ PLL。**最初は 400MHz(VOS1)**、動いてから 520MHz(VOS0)に上げる。550MHz(CPU_FREQ_BOOST)は要るときだけ | VOS0 はコアの電圧が上がり、SMPS ではジャンクション 105°C まで。最初は余裕のある設定で、ほかの問題と切り分ける |
| キャッシュ | 命令のキャッシュは最初から ON。データのキャッシュは最初 OFF、動いてから ON | `docs/firmware_memory.md` の決まり(DMA は SRAM1・2、MPU でキャッシュしない)を守っていれば、ON にしても壊れない |
| RAM | ふつうの変数・スタックは DTCM、DMA の配列は SRAM1・2(`DMA_BUF`)、ログ(256KB)は AXI SRAM、20kHz・10kHz の割り込みの関数は ITCM | 割り込みは待ちのないメモリで速く |
| 最適化 | -O2、`-Wall -Wextra -Wdouble-promotion` | MK3 は -O0 だった。float の計算が double にならないように警告を出す |
| 数 | `float`(単精度)を基本にする。定数は `0.5f` のように f を付ける | H725 は倍精度の FPU も持つが、単精度のほうが速く、MK3 のコードも float |
| ウォッチドッグ | IWDG 約 50ms。1kHz の処理で、20kHz・10kHz の処理が動いているのを確かめてからクリア | 割り込みが止まったらリセットして止まる |

## 4. 時刻の作り方(タイマー・ADC・DMA)

### 4.1 元の時刻: TIM1

- TIM1 はモーターの PWM(CH1〜CH4 = 左右の IN1・IN2、`docs/pinmap.md`)。**センターアラインド**(山と谷がある三角の数え方)にする
- PWM の周波数は **40kHz から始める**(モーターのインダクタンスを測ってから 40〜80kHz で決める、`docs/control.md`)。TIM1 のクロック 275MHz で、40kHz のとき 1 周期 3438 カウント(約 11.7 ビット)
- TIM1 の繰り返しのカウンタで、**2 周期に 1 回(20kHz)**更新の割り込みと ADC2 の起動を出す
- 吸引のファンの TIM16 は、TIM1 と**同じ周期にして同時にスタート**する(TIM16 にはほかのタイマーに合わせる仕組みがないが、同じクロックなのでずれない)。壁センサを読む位置が、車輪とファンの PWM のいつも同じ所になる(`docs/review_2026-11-06.md` の「ソフトでやること」)

### 4.2 ADC2: モーターの電流と電池(20kHz)

- TIM1 の TRGO(PWM の山 = 真ん中)で起動。5 本を順に読む: MOT_L_I、MOT_R_I、MOT_L_CMS、MOT_R_CMS、BATT
- INA241A3 はシャントの電圧をいつも測るので、PWM の真ん中で読むと **1 周期の平均の電流**に近い
- 読み終わり(DMA の終わり)で **20kHz の割り込み**(4.4)

### 4.3 ADC1: 壁センサとファンの電流

- TIM1 の TRGO2(内部の比較 OC6)で起動。**OC6 の値で、発光を点けてから読むまでの時間を決める**(約 7µs 以上。NJU6080 の遅れ 2.5µs + 受光のアンプが落ち着くまで、`docs/spec.md` の「制御周期」)
- 20kHz の割り込みを 5 つの順番(スロット)に分けて、**4kHz で 1 巡**する:

| スロット | 発光 | ADC1 で読むもの |
|---|---|---|
| 0 | なし | FL・L・R・FR の消灯の値(外の光とオフセット)、ファンの電流 |
| 1 | FL と R(WALL_LED_FL_R) | FL・R |
| 2 | L と FR(WALL_LED_L_FR) | L・FR |
| 3・4 | なし | (空き。あとで、2 回読んで平均するなどに使う) |

- 壁センサの値 = 点灯の値 − 消灯の値(MK3 と同じ考え)。対角の 2 個ずつ光らせるので、隣のセンサの光が入りにくい(MK3 の WallLED_12・WallLED_34 と同じ組)
- 発光は 1 回 10µs ほどで、4kHz なので平均の電流はごく小さい

### 4.4 20kHz の割り込み(いちばん優先度が高い)

ADC2 の DMA の終わりで動く。HAL の関数は使わず、レジスタを直接読む・書く。

1. 電流を mA に直す(0A の値は起動のときに測る。左右・ゲインは同定の値)
2. **電流の守り**: 目標を ±3A(パラメータ)で頭打ち。測った電流が 5A を 1ms 超えたら止める(7章)
3. **電流の制御**: duty = (R × 目標 + Ke × モーターの角速度) / 電池の電圧 + PI(目標 − 測った電流)。duty の上限も毎回計算(`docs/control.md` の4章)。回生の電流の制限もここ
4. TIM1 の比較の値を書く(次の周期から効く)
5. 壁センサのスロットを進め、次のスロットの発光を点ける・消す
6. 偶数回目は、エンコーダの読み取り(SPI2 の DMA)を始める(10kHz)
7. 20 回に 1 回、**1kHz の処理を起こす**(優先度の低い割り込みを `NVIC_SetPendingIRQ` で)
8. 処理時間を測る(DWT のカウンタ)。いちばん長かった値をログに残す

目安: 400MHz で 3〜5µs(50µs の 1 割以下)。

### 4.5 エンコーダ(10kHz)

- MT6835 × 2 を SPI2 で読む(12.5MHz 以下、CS を下げてから 100ns 以上待つ。`docs/review_2026-11-06.md`)。左を読み終わった DMA の割り込みで、右を始める
- 角度は 21 ビット。CRC を確かめ、合わなければ前の値を使い、回数を数える
- 読み終わりで速度の推定(5.1)

### 4.6 IMU(6.66kHz)

- LSM6DSR の INT1(データの準備ができた)を PD2 の EXTI で受け、SPI3 の DMA で角速度と加速度(12 バイト)を読む
- 推定は「いちばん新しい値」を使う(1kHz の処理の中で、その間の値を平均してもよい)

### 4.7 1kHz の処理

20kHz の割り込みから起こされる、優先度の低い割り込み。軌道 → 位置・向き → 速度・角速度 → 電流の目標、壁制御、フェイルセーフ、ログ(6章)。目安 20〜50µs。

### 4.8 割り込みの優先度

| 優先度 | 処理 | 周期 | 目安の時間 |
|---|---|---|---|
| 0(高) | ADC2 の終わり = 20kHz の処理 | 50µs | 3〜5µs |
| 1 | SPI2・SPI3 の DMA の終わり、IMU の INT1 | 100µs・150µs | 1〜2µs |
| 2 | 1kHz の処理 | 1ms | 20〜50µs |
| 3 | UART の DMA、SysTick | | 短い |
| なし | メインのループ | | |

合わせて CPU の 1〜2 割。残りはメインのループ(迷路の計算など)。

## 5. 制御

中身は `docs/control.md`。ソフトの作りとして決めること:

### 5.1 推定(`estimator.c`)

- 10kHz: 左右の車輪の角度 → 速度。加速度との相補フィルタで並進の速度 v(`docs/control.md` の2章)
- 1kHz: 角速度 ω はジャイロ(止まっているときにバイアスを測る)、向き θ は積分、位置 x・y は v・θ の積分。壁で補正(壁制御・壁切れ)
- 出口は構造体 `est_t`(v、ω、θ、x、y、左右の車輪の速度、加速度)。中身をカルマンフィルタに替えても、ほかは変えなくてよい

### 5.2 制御(`current_ctrl.c`・`motion_ctrl.c`)

- **カスケード**: 位置・向き(1kHz)→ 速度・角速度(1kHz、あとで 2〜5kHz)→ 左右の電流(20kHz)
- 速度・角速度は**並進と回転に分けて**、和の電流・差の電流を出す。軌道の加速度・角加速度はフィードフォワードで電流に直接入れる
- 上の段(位置・向き)の出口は「v・ω の目標への補正」にそろえ、**MK3 方式(壁制御だけ)と軌道追従を差し替えられる**ようにする(`docs/control.md` の「位置・向き」)
- ゲイン・制限はすべてパラメータの表(8.2)に置き、BLE・UART で変えられる

### 5.3 軌道(`trajectory.c`)

- 直線: 台形(あとで加速度も滑らかにする)。目標の位置・速度・加速度を 1kHz で出す
- ターン: MK3 の形(前距離・角速度の形・後距離)を持ってくる。角速度と角加速度の目標も出す(フィードフォワード用)
- ターンのパラメータは、ターンの種類 × 速度の表(MK3 の ShortParam)。Flash に保存し、`turn_test` で自動で合わせる(`docs/ble.md` の5章)

## 6. 状態とモード

### 6.1 走る状態

```
  起動 → 待ち(IDLE)──手をかざす──→ 準備(ジャイロのバイアス、0A の値)→ 走る(RUN)
            ↑                                                        │
            └──── 終わった(DONE: Flash に保存 → つながっていれば送る)←──┘
  どの状態からでも: 止める条件(7章)→ 止まった(FAULT: LED の点滅、スイッチで待ちへ)
```

- 走っている間は、コマンドは `stop` だけ受け付ける(`docs/ble.md` の3章)。Flash にも書かない
- 待ち・終わったときは、すべてのコマンドを受け付ける
- 待ちの間は MOT_EN を L(ドライバのスリープ)にし、ファンも止める

### 6.2 モードの選び方

- MK3 と同じく、**車輪を手で回してモード(LED 3 ビット = 0〜7)と番号(LED 4 ビット = 0〜15)を選ぶ**。スイッチ(SW2)で決める
- スタートは MK3 と同じ: 前のセンサに手をかざす → ブザー → 横のセンサに手をかざすと走る
- BLE・UART の `run <種類>` でも同じ手順(手をかざしてから)で走る。番号の表は MK3 の README の「モード」を元に、MK4 用に作り直す(電流の同定・turn_test を足す)

## 7. 止める条件(フェイルセーフ)

| 条件 | 見る所 | すること |
|---|---|---|
| モーターの電流が 5A を 1ms 超えた | 20kHz | すぐ duty 0・EN を L |
| nFAULT が L(MP6551 の過電流・過熱) | 1kHz(PC9) | 止める |
| 目標と推定のずれが大きい(ぶつかった・滑った) | 1kHz | 止める(MK3 の `Failsafe_MotorTagetdiff` と同じ考え) |
| 電池が 11.3V を下回った(止まっているときの値か、時間の平均) | 1kHz | 走っていれば止める。待ちなら LED で知らせる。さらに下がったら、LED・ファンを消して待つだけにする |
| 20kHz・10kHz の処理が止まった | 1kHz(回数の数え) | 止める。1kHz も止まれば IWDG がリセット |
| エンコーダ・IMU の CRC・読み取りの失敗が続いた | 1kHz | 止める |
| 回生で電池の電圧が上がった(13.5V 超) | 20kHz | 回生の電流の制限を強める(`docs/control.md` の「電流」) |

- 止まったら: モーター・ファンを止め、LED を全部点滅(MK3 と同じ)。**スイッチを押すと待ちに戻る**。探索中なら、最後に保存した迷路が残っている(MK3 と同じ)
- 止まった理由はログと `#STATUS` に残す

## 8. 保存(内蔵 Flash)

### 8.1 Flash の分け方

`docs/spec.md` の「内蔵Flashの使い方」と `docs/ble.md` の6章:

| セクタ | 大きさ | 中身 |
|---|---|---|
| 0 | 128KB | ブートローダ(無線の書き込みでは消さない) |
| 1〜3 | 384KB | 走るプログラム(先頭に見出し: 印・長さ・CRC32) |
| 4・5 | 256KB | パラメータ・迷路(2 つを交互に使う) |
| 6・7 | 256KB | ログ |

### 8.2 レコード

- 1 つのセクタに、レコードを**後ろへ足していく**(32 バイト単位。同じ所は消さないと書き直せないため)
- レコード = 見出し(印、種類、通し番号、長さ、CRC32)+ 中身。読むときは、CRC の合う**いちばん新しい通し番号**を使う
- いっぱいになったら、もう片方のセクタに最新を全部書いてから、古いほうを消す。書いている途中で電源が切れても、前のものが残る
- **書くのは止まっているときだけ**(消すのに時間がかかり、その間 Flash を読めなくなることがあるため)。書いたあとに読み直すときは、その範囲のキャッシュを捨てる(`docs/firmware_memory.md` の5章)

### 8.3 パラメータの表(`params.c`)

- パラメータは 1 つの表で持つ: 名前(`turn90.entry_acc` など)、型、初めの値、下限・上限、説明
- `get params`・`set`・`save` はこの表を見て動く。**新しいパラメータは表に 1 行足すだけ**で、BLE からも変えられ、Flash にも保存される
- MK3 では会場ごとの感度(`WallDist_Scale` など)を書き写してビルドし直していた。MK4 では `set` → `save` で済む
- 中身の形が変わったら(版の番号)、表にない名前は捨て、足りない名前は初めの値にする

## 9. ログ(`logger.c`)

- MK3 の考え(`KOGUMA.MkIIl/docs/log_design.md`)を引き継ぐ: **どの問いに答えるかで列を決める**、列はいつも全部取る、値は int16(単位を決めた整数)、`phase`(何の動作中か)を残す
- MK4 で足す列: **左右の電流の目標と測った値、左右の duty、電池の電圧、左右の車輪の速度、推定の速度と加速度、ジャイロ**、CMS(電池の電流の目安)、エンコーダ・IMU のエラーの数、割り込みの最長の時間
- 置き場所は AXI SRAM の 256KB。1 行 64 バイトなら、1ms ごとで約 4 秒、4ms ごとで約 16 秒
- **短い高速のログ**: 電流の制御を合わせるとき用に、20kHz で電流・duty だけを 0.1 秒ほど取るモードも持つ
- 終わったら Flash に書き、つながっていれば送る(`docs/ble.md` の3章)。形は MK3 と同じ(`#BEGIN LOG …` + 1 行目が列の名前の CSV)なので、**MK3 のビューアで読める**

## 10. 通信

`docs/ble.md` のとおり。ソフトの作りとして:

- USART1 は DMA で送り、受けは DMA のリングバッファ(`DMA_BUF` に置く)。**1Mbaud**(STLINK-V3 の仮想 COM ポートで使えるか確かめる)
- 受けた行は割り込みの中では処理せず、メインのループで `cmd.c` が読む
- 送るときは、大きなログを 4KB ずつ `DMA_BUF` の送り口に写して、交互に送る(`docs/firmware_memory.md`)。XOFF が来たら止める
- 有線と無線はどちらも同じ UART に見える。区別しない

## 11. ブートローダと書き込み

`docs/ble.md` の6章のとおり。

- ブートローダは別のプロジェクト(`firmware/bootloader/`)。D キャッシュは OFF、HAL は最小限
- 起動のたびに待たずに、走るプログラムの CRC を確かめて飛ぶ。書き込みの待ちに入るのは、印があるとき・UART_RX が L のとき・プログラムが壊れているときだけ
- 走るプログラムは 0x08020000 から。最初に VTOR を設定する
- 有線(STLINK)で書くときのために、走るプログラムの ELF にブートローダも入れる(リンカの設定)

## 12. テスト

### 12.1 PC で動かすテスト

MK3 のテスト(迷路・最短経路・未知の壁の探索・距離変換・速度計画・距離ごとの履歴・柱の端)をそのまま持ってくる。新しく足すもの:

| 電流の制御 | モーターのモデル(R・L・Ke、電池の内部抵抗)を PC で動かし、目標の電流に追いつくか、3A で頭打ちになるか、回生で電圧が上がりすぎないか |
| 推定 | 作った加速度とエンコーダの値(ノイズ・バイアス入り)から、速度が正しく出るか |

- ハードに触るもの(`board/`)と、それ以外を分けておけば、それ以外は全部 PC でテストできる

## 14. 書き方の決まり

- 単位は名前に付ける(`v_mmps`、`omega_radps`、`i_mA`、`dt_s`)。中は mm・mm/s・rad・rad/s(MK3 と同じく mm)
- 座標は機体の座標(x 前、y 左)。角度は左回りが正
- グローバルな変数(MK3 の `G_*`)は減らし、モジュールごとの構造体にする。割り込みとメインのループで分け合う値は `volatile` と、書き換えの順番(または割り込みを止める短い区間)に気をつける
- 20kHz・10kHz の割り込みの中では、HAL の関数・`printf`・割り算の多い計算・Flash の操作をしない
- コメントと文書は日本語。MK3 から持ってきたものは、出どころ(ファイル名)を書いておく
